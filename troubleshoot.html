When the AI Assistant panel doesn't appear

Three checks, a few minutes each. Each one prints what it found, and the table under it says what that means and which fix to go to. If it's still unclear, send the outputs over: they hold no keys or passwords.

The panel has to get past five things before it shows: Superset has extensions turned on, Superset loads the plugin's .supx, your role may load extensions, the browser runs this version of the plugin, and your role has a permission on nltosqlandback.

The commands below follow these. Saved in this browser.

0. Which build should be running

In your checkout of this repo, the one you built the .supx from:

git rev-parse --short HEAD

That's the commit the checks below should report. If the build was made with uncommitted changes, they say <commit> with local changes.

Check the .supx you built has the panel's code in it:

unzip -l nltosqlandback-0.1.0.supx | grep remoteEntry

No line means the frontend build failed. superset-extensions bundle prints ❌ Frontend build failed and then carries on, writing a .supx with only the backend in it. To see why it failed, run the frontend build on its own and look at the first error:

cd frontend && npm run build

troubleshoot-build.html checks the build machine and says what the errors mean.

1. In the browser

  1. Open SQL Lab, signed in as the user who can't see the panel.
  2. Open the browser's developer tools and go to Console: F12, or Cmd+Option+J on a Mac (Chrome, Edge) / Cmd+Option+K (Firefox).
  3. Copy the block below and paste it into the console, then press Enter. The first time, Chrome and Firefox refuse the paste and ask you to type allow pasting first. Do that, then paste again.
  4. It prints a report and, last, a one-line answer. The report is also copied to the clipboard where the browser allows it; otherwise copy it from the console.

Fixes



Turn extensions on


Superset needs "ENABLE_EXTENSIONS": True in FEATURE_FLAGS and EXTENSIONS_PATH
set, in the config it actually reads (check 2's first line names it).




With the Helm chart, put them in the values' configOverrides. The chart adds each entry to the
superset_config.py it writes, so this keeps any feature flags set earlier:


configOverrides:
  extensions: |
    FEATURE_FLAGS = {**globals().get("FEATURE_FLAGS", {}), "ENABLE_EXTENSIONS": True}
    EXTENSIONS_PATH = "/the/folder/holding/the/supx"


Don't paste the top of deploy/superset_config_docker.py into the Helm values: its
from superset_config import FEATURE_FLAGS and its EXTENSIONS_PATH are for Superset's
docker compose. Copy its NLSQL_* lines.




With Superset's docker compose, deploy/superset_config_docker.py goes in
docker/pythonpath_dev/. If it fails to import, Superset says Using default Docker config
in the log and carries on without it.


Then restart:





Put the .supx where Superset looks


Superset loads every *.supx in EXTENSIONS_PATH, inside the container, at start-up.
Check 2 lists what's there. Either put the file in that folder, or point EXTENSIONS_PATH at where it
is, then restart (above).



Replace an old .supx


If check 2's build isn't the one from step 0, the container has an old file. Copy the new one in and restart.
Superset reads the .supx only at start-up, so copying it in isn't enough on its own.


If the .supx is baked into an image: a new image pushed under the same tag isn't
pulled when imagePullPolicy is IfNotPresent. Use a new tag, or set it to
Always and restart.



Let the role load extensions


This is Superset's check, before the plugin runs. The user needs a role with can get list and
can content on ExtensionsRestApi. Gamma, Alpha and Admin have them; sql_lab on its own
doesn't. Add them in Settings → List Roles → edit the role → Permissions. Without them the console shows
Error setting up extensions with a 403 on /api/v1/extensions/.



Give the panel permission


The plugin shows its panel to users with any permission on nltosqlandback. Gamma, Alpha and Admin
get them from superset init. For another role, add one, such as can generate sql on
nltosqlandback, in Settings → List Roles. Or build the .supx with
NLSQL_IGNORE_ROLES=true to show it to everyone.



Our settings aren't read


If check 2's plugin line shows the defaults (key not set, structure read per_table,
dictionary none) where you set something, the NLSQL_* lines aren't in the config file
Superset reads. Put them there (as above) and restart.



Open the sidebar


The panel lives in SQL Lab's right-hand sidebar, which can be collapsed. Look for its toggle at the right edge.
