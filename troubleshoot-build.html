When the .supx build fails

Building the extension is .venv/bin/superset-extensions bundle in this repo. It builds the frontend (the panel) with Node, copies the backend, and zips both into nltosqlandback-0.1.0.supx.

If the frontend build fails, bundle prints ❌ Frontend build failed and carries on: it still writes a .supx, with only the backend in it. Superset loads that happily and the panel never appears. So check the .supx after every build (step 3).

When the server side looks fine and the panel still doesn't appear, see troubleshoot.html.

What the build needs

gitanyOptional. The build puts the commit in its label; without git it says unknown commit.

The .supx is the same file wherever it's built. If the site's machines can't build it, build it anywhere that can, from the same commit, and copy the file across.

1. Check the build machine

In a terminal, go to your checkout of this repo, paste the block below and press Enter. It checks the tools, then runs the frontend build on its own and shows its first errors. It changes nothing outside frontend/dist, and it doesn't download anything unless node_modules is missing, when it only pings the registry.



The full build output goes to nlsql-frontend-build.log in your temp folder; the
last line says where. It prints whether a proxy is set, never its value.

3. Build the .supx and check it


When step 1 ends with frontend build OK, from the repo's root:


.venv/bin/superset-extensions bundle 2>&1 | tee "${TMPDIR:-/tmp}/nlsql-bundle.log" | grep -E "✅|❌"
unzip -l nltosqlandback-0.1.0.supx | grep remoteEntry || echo "NO FRONTEND IN THE .supx: don't install it"


Every line should be ✅, and the last line should name a remoteEntry….js file. Then install the
.supx and restart Superset, and check from SQL Lab with troubleshoot.html.
