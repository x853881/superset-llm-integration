How to read the colours

Got worseNo changeGot better

Colour and arrow both show the change in pass rate, in percentage points. The deeper the colour and the steeper the arrow, the bigger the change: flat is no change, straight up or down is a move of 50 points or more. dashed outline = fewer than 10 attempts in a run, so read it with care. Colour shows change, not level, so each tile also has a bar : its length is the pass rate in the later run and the tick is the earlier run's. An empty bar is a check that never passes, however grey the tile.

By endpoint and metric

Each row is a plugin endpoint, worst change first. The outlined tile is the share of attempts that passed every check; the other tiles are individual metrics. Every attempt counts as the run recorded it: a judged metric the judge wasn't asked, because a check that the answer is right had already failed, counts as failed. Hover a tile for the counts; click it to list the goldens behind it.

By question

Each golden's pass rate in both runs. Dots are attempts in order (filled = passed, hollow = failed). Tier is report.py's: A passed every attempt, B more than half, C some, D none. “Failing now” lists every golden that failed at least once in the later run, changed or not. Click a row for the metrics that moved and every attempt's answer, checks and reasons; click a column heading to sort.

Speed and reliability

How long the plugin took to answer: each golden's median time, then the median of those, so a golden asked more often doesn't count for more. Slowest change first. Over the time limit counts failed Plugin Latency checks; a crash is a request that failed or whose response couldn't be read; a retry is the plugin asking its model again, for example after invalid SQL.
